  2. 2 · BLOCKED BY 1 · Derive the parameters, do not inherit them

    Replace gold's numbers with BTC-derived ones

    • Every strategy value in btc/config.py is marked PLACEHOLDER: ATR_MIN = 0.0 (filter off rather than derived), SL 2.0 / TP 5.0 ×ATR, BE 1.5R, MAX_DAILY_LOSS = 8.0, MAX_TRADES_PER_DAY = 15.
    • MAX_SPREAD_POINTS = 6250 is the one measured value (1.25× TRAIN p90, 2026-10-03). It is an observation gate that lets FORWARD_TEST see quotes — not a strategy approval.

    Exit gate: a reviewed parameter table with provenance. Not a value edited in place because it looked better.

  3. 3 · PARALLEL PREPARATION · 24/7 mechanics that gold does not have

    Broker recon, swap and blackout windows

    • btc/recon.py must confirm the exact symbol name, digits, contract size, stops level, filling mode, swap (including Friday's triple swap) and the server's UTC offset.
    • ENTRY_BLACKOUTS_ENABLED = False until that offset is confirmed — a wrong offset blanks the wrong hour, so the rollover and Saturday-maintenance windows stay off by choice.
    • The engine does not model swap P&L at all, and WEEKEND_FLAT_ENABLED = False by the 2026-10-24 decision (a risk judgement, not a measured BTC result). A position can therefore be held across a weekend with financing the backtest never charges.

    Exit gate: a recon report filed with the offset and swap values recorded, then an explicit decision on blackouts and weekend holding.

    Sources: btc/HANDOFF.md, btc/config.py, docs/btc_market_reference_2026-10-03.md, STATUS.md

  4. 4 · BLOCKED BY 2 AND 3 · Demo execution drill (BTC-specific)

    Exit gate: a demo execution report plus a realized-R tolerance agreed in advance. Fake-terminal tests are not a broker drill.

    Source: docs/live_readiness_review_2026-10-23.md §6 (applies to the shared engine), btc/logs/paper_account.json
