# Redesign — Hybrid Shared / Isolated LIVE Architecture (2026-10-04)

**Branch:** `arena/01a106bd-scalper` | **Status:** Design approved — hybrid, BTC re-hypothesis, split dashboards + portfolio overlay
**Decisions:** `ACCOUNT_MODE=shared|isolated` in one `.env` · keep `8088` gold + `8089` btc · BTC stays disabled until a new Phase-1c hypothesis passes on *untouched* data.

## 0. TL;DR — your question answered first

> *"For now both just use one XM account — could both run LIVE one day sharing the same credential in `.env`?"*

**Yes. You already do.** `docker-compose.yml` does `env_file: - .env` → one MT5 container → one login (`MT5_LOGIN`/`MT5_SERVER`) → one RPyC bridge `localhost:18812` → both `run.py` and `btc/run.py` connect to the *same* terminal. In `FORWARD_TEST` that's harmless (no `order_send`).

**Flipping both to `TRADING_MODE="LIVE"` *today* would technically place real orders on the same equity pool, but it would be unsafe.** `btc/HANDOFF.md` §8-risk-5 and `HANDOFF.md` §5 block it for a reason, and the code has a latent bug that makes it worse. The redesign below makes *shared-credential LIVE* safe while also letting you split to two logins later without rewriting anything.

BTC itself is a separate gate: Phase-1b proved the current EMA200/RSI/ATR shape has **no edge on BTCUSD at XM's spread** (`-165.84 PF 0.74` over 20k M5, `spread/risk 26%` vs gold `5%`, required WR `36%` vs actual `23.8%`). A redesign must not `TRADING_MODE="LIVE"` BTC on the same shape — it must make it *easy to test a new shape* on *untouched* data and trivial to keep BTC disabled until that gate passes. That's built in.

## 1. How today's sharing actually works (and why paper mode hides the problem)

```
.env  ──env_file──►  docker compose → mt5 (Wine, lprett-mt5linux-patched)
                         │  :18812 RPyC  ─┬─► scalper-bot (GOLD,  MAGIC 999111, logs/ , :8088)
                         │                └─► scalper-btc-bot (BTCUSD, MAGIC 999112, btc/logs/, :8089)
                         │  single XM login (MT5_LOGIN) → single balance/margin/deal history
```

* **Isolation that *does* work:** `MAGIC_NUMBER` split, `LOG_DIR` split (`logger.py` via `config.LOG_DIR`), `CONTRACT_SIZE`/`PRICE_DIGITS` per instance, `ORDER_COMMENT` distinct. `positions_get(symbol).magic` filtering + `LiveLedger` magic filtering prevents one book from closing the other's simulated trade.
* **Isolation that *does not* work in LIVE:** `daily_stats.json` / `live_ledger.json` / `MAX_DAILY_LOSS` / `MAX_TRADES_PER_DAY` are **per-`LOG_DIR`**. Two bots can each be `-$20` on a `-$30` gate while the *account* is `-$40`. `order_calc_margin` sees the shared `margin_free`. Swap/rollover, weekend gaps, and spread economics are per-symbol but debited from one pot.

Paper mode masks all of this because `PaperAccount` never calls `order_send`; both books are just JSON on disk.

## 2. Six blockers that make shared-LIVE unsafe TODAY

| # | Blocker | Where | Why it hurts shared-LIVE | Fix in redesign |
|---|---|---|---|---|
| **1** | **Per-instance risk gates** | `run.py:140` + `logger.daily_stats` + `live_ledger.py` | Account can be `-2× gate` and both bots still enter. `btc/HANDOFF.md` §8-5 hard blocker. | **PortfolioRiskManager** — one JSON + one file gate both bots check |
| **2** | **`MT5Bridge.close()` calls `mt5.shutdown()`** | `mt5_bridge.py:373` | Either bot reconnecting (`consecutive_errors ≥3`) shuts the MT5 session for *both*. `btc/recon.py` deliberately avoids shutdown for this reason; the engine doesn't. On a shared bridge this is a self-inflicted outage. | Never call `shutdown()` on shared bridge; add `SHARED_BRIDGE=True` / ref-count; probe without shutdown |
| **3** | **`wait_for_mt5.py` also probes with `mt5.initialize/shutdown`** | `wait_for_mt5.py:probe_mt5` | Same — `ExecStartPre` of the second unit can kill the first's session during boot. | Probe without shutdown when shared |
| **4** | **No combined margin / no hedge awareness** | `mt5_bridge._margin_ok` per-bot | Bot A opens, bot B's `margin_free` check still passes because it hasn't accounted for A's pending margin until next `account_info` poll | Portfolio gate reads `account_info.margin_free` once + reserves; or let broker reject and surface cleanly |
| **5** | **No atomic bridge lock** | `MT5Bridge.get_rates` / `order_send` | One RPyC `SlaveService`, one `MetaTrader5` module, two clients calling `symbol_select`/`copy_rates_from_pos` concurrently — historically mitigated by 15s loop but not guaranteed | Add `threading.Lock` per bridge + single canonical `HOST:PORT`; or add a thin `mt5_proxy` service |
| **6** | **Deploy & observability split** | `deploy.sh` `SERVICES` default, `btc/server_check.py` | No single view of "portfolio health" | Unified `deploy.sh` default + portfolio overlay in dashboards |

All six are fixed without forking the engine.

## 3. Hybrid architecture — one `.env`, two modes

```
                    ┌─ ACCOUNT_MODE=shared ─────────────────────┐
                    │  .env: MT5_LOGIN / MT5_PASSWORD / ...     │
                    │  docker-compose: mt5 (18812)             │
                    │  bots → same bridge, same equity         │
                    │  PortfolioRiskManager enforces combined   │
.env  ──────────────┤   MAX_DAILY_LOSS / MAX_TRADES via         ├─► Dashboards
                    │   logs/portfolio.json + KILL_SWITCH       │    :8088 gold
                    │                                           │    :8089 btc
                    └─ ACCOUNT_MODE=isolated ───────────────────┘    :8088/portfolio
                    │  .env: MT5_GOLD_LOGIN + MT5_BTC_LOGIN     │    (overlay)
                    │  docker-compose: mt5-gold (18812)         │
                    │                mt5-btc  (18813)           │
                    │  bots → different bridge+equity           │
                    │  gating still combined *or* per-account   │
                    └───────────────────────────────────────────┘
```

* **Single knob:** `ACCOUNT_MODE` in `.env` (default `shared` for today). Code reads `MT5_*` in shared mode, `MT5_GOLD_*` / `MT5_BTC_*` in isolated mode with fallback to `MT5_*`.
* **No code fork:** engine becomes `Engine(config)` dependency-injected; `_instance.py` monkey-patch becomes a factory, not a `sys.modules` hack.
* **Dashboards:** keep `8088` + `8089` exactly as now (no URL break), add `GET /api/portfolio` + a tiny `portfolio.json` writer — both boards render the same banner: `Portfolio PnL / Trades / KILL_SWITCH`.

## 4. `.env` v2 — one file, both futures

```ini
# ——— mode ———
# shared  = one XM login, one container, one equity pool (today, and valid for paper)
# isolated= two logins, two containers, two equity pools (future, clean LIVE split)
ACCOUNT_MODE=shared

# ——— shared mode (what you have today) ———
MT5_LOGIN=
MT5_PASSWORD=
MT5_SERVER=XMGlobal-MT5 17
VNC_PASSWORD=

# ——— isolated mode (only needed if you split) ———
# When ACCOUNT_MODE=isolated, GOLD reads MT5_GOLD_* (fallback MT5_*), BTC reads MT5_BTC_*
# Leave blank while shared.
MT5_GOLD_LOGIN=
MT5_GOLD_PASSWORD=
MT5_GOLD_SERVER=
MT5_BTC_LOGIN=
MT5_BTC_PASSWORD=
MT5_BTC_SERVER=
MT5_BTC_VNC_PASSWORD=

# ——— bridge ———
# In isolated mode the BTC bridge moves to 18813 so two Wine prefixes don't collide
MT5_HOST=localhost
MT5_GOLD_PORT=18812
MT5_BTC_PORT=18813
```

`docker-compose.yml` becomes:


`docker compose --profile isolated up -d` is the only difference. In `shared` mode the second service never starts — zero overhead.

## 5. Engine refactor — kill the `sys.modules` hack, keep gold proven

**Today:** `btc/_instance.py:activate()` does `sys.modules["config"] = btc.config` before engine import. Works, but fragile (`research/*` does `sys.path.insert(0, root)`), and impossible to run both instances in one process (needed for portfolio gate/tests).

**Redesign:**

```python
# core/config.py — dataclass, not import magic
@dataclass(frozen=True)
class InstanceConfig:
    symbol: str
    magic: int
    log_dir: Path
    host: str; port: int
    trading_mode: str
    # ... all current config.py keys
    @classmethod
    def from_env(cls, instance: str) -> "InstanceConfig": ...
    @classmethod
    def from_file(cls, path: Path) -> "InstanceConfig": ...

# core/engine.py
class Engine:
    def __init__(self, cfg: InstanceConfig, bridge: MT5Bridge, portfolio: PortfolioRiskManager):
        self.cfg = cfg
        self.strategy = ScalpStrategy(cfg)
        self.paper = PaperAccount(cfg) if cfg.trading_mode=="FORWARD_TEST" else None
        self.ledger = LiveLedger(cfg) if cfg.trading_mode=="LIVE" else None
```

* `ScalpStrategy`, `PaperAccount`, `MT5Bridge`, `LiveLedger`, `logger` all take `cfg` — no global `import config`.
* Backwards compat: `config.py` / `btc/config.py` remain as `InstanceConfig` factories (`get_config() -> InstanceConfig`) so `btc/tool.py` still works, but new code imports `core.*`.
* **Gold proof preserved:** `backtest.py` `255 / +$456.58 / PF 1.32 / maxDD 108.65 / 72-43-140` and `parity_test.py 460 signals 0 mismatches` are the gate — any refactor that moves them fails CI.

Migration is mechanical: rename `config.*` → `cfg.*` inside functions, thread `cfg` through. No strategy logic change.

## 6. Bridge fix — shared-termination bug

```python
# mt5_bridge.py
class MT5Bridge:
    def __init__(self, cfg: InstanceConfig):
        self.cfg = cfg
        self._shared = (os.getenv("ACCOUNT_MODE","shared")=="shared")
        # ...

    def close(self):
        if self._closed: return
        self._closed = True
        if not self._shared:
            try: self.mt5.shutdown()
            except: pass
        try: self.conn.close()
        except: pass

    # add lock
    _global_lock = threading.Lock()
    def get_rates(self, ...):
        with self._global_lock:
            return self._get_rates_inner(...)
    def open_trade(self, ...):
        with self._global_lock:
            return self._open_trade_inner(...)
```

* `wait_for_mt5.py` gets `--shared` flag → probes `initialize()` but never calls `shutdown()` when shared.
* Concurrency probe (`btc/HANDOFF.md` §7) becomes a CI test: 20 parallel `copy_rates_from_pos` for GOLD+BTCUSD must not disturb `scalper-bot`.

## 7. Risk — per-instance + portfolio (the thing that makes shared-LIVE valid)

```
logs/gold/daily_stats.json ─┐
logs/btc/daily_stats.json  ─┤─► PortfolioRiskManager (core/portfolio.py)
live_ledger gold+btc deals ─┘      writes logs/portfolio.json + logs/KILL_SWITCH*
```

* `core/portfolio.py`:

```python
@dataclass
class PortfolioState:
    date: str
    pnl: float          # sum of both instances' realized today
    trades: int
    per_instance: dict  # {"GOLD": {...}, "BTCUSD": {...}}

class PortfolioRiskManager:
    def __init__(self, cfg_gold, cfg_btc, limits: PortfolioLimits):
        self.limits = limits  # e.g. MAX_DAILY_LOSS=35, MAX_TRADES=25 when shared

    def check(self) -> tuple[bool,str]:
        # reads both daily_stats + both live_ledger deal histories atomically
        # returns (blocked, reason)
    def record_pnl(self, instance: str, pnl: float, is_win: bool):
        # updates both per-instance and portfolio atomically (file lock)
```

* `run.py` loop:

```python
blocked, reason = portfolio.check()
if blocked:
    log_system("WARNING", f"PORTFOLIO GATE {reason} — new entries disabled")
    # optionally touch per-instance KILL_SWITCH so both dashboards show it
    time.sleep(300); continue

# existing per-instance gates stay — defense in depth
if stats["pnl"] <= -cfg.max_daily_loss: ...
```

* Limits in shared mode are **not** `gold 30 + btc 8 naïvely**. Re-derive from combined backtest:
  * Gold risk ~$6 median SL, BTC ~$1.6 at 0.01 lots. Combined 99th percentile daily loss on *both* playing → portfolio `MAX_DAILY_LOSS` ≈ `35–40` (not 38) + `MAX_TRADES_PER_DAY` ≈ `20–25`.
  * In isolated mode each account keeps its own gate; portfolio gate becomes advisory.

* `KILL_SWITCH` becomes `logs/KILL_SWITCH` (portfolio) + `logs/gold/KILL_SWITCH` + `logs/btc/KILL_SWITCH` — touching any disables that instance; touching the portfolio one disables both. Dashboard shows which.

This satisfies `btc/HANDOFF.md` §8-risk-5: the hard combined gate exists *before* any LIVE flip.

## 12. Migration — zero-downtime, no paper-clock reset

**Principle:** paper clocks (`logs/paper_account.json`) carry across restarts only if `LOG_DIR` and `STATE_FILE` paths don't move. So:

1. **Add** `core/*` + new `.env.example` + new `docker-compose.yml` (both modes). Don't delete old files yet.
2. **Thread `cfg`** through engine but keep old `import config` fallback via `getattr` — gold backtest still `255 / +$456.58`.
3. **Add** `PortfolioRiskManager` as library (no new service). Both bots start writing `logs/portfolio.json` next deploy; dashboards tolerate missing file.
4. **Fix** `MT5Bridge.close()` + `wait_for_mt5.py` (`SHARED` flag).
5. **Cut** `btc/_instance.py` to factory wrapper (`InstanceConfig.from_file("btc/config.py")`), delete `sys.modules` hack.
6. **Re-derive** portfolio limits: `btc/derive_params.py` (BTC) + gold `loss_analysis` → propose `PORTFOLIO_MAX_DAILY_LOSS=35`, `PORTFOLIO_MAX_TRADES=25` (shared mode).
7. **Test** on server: `btc/tool.py --check` `11/11` → `12/12` (new portfolio check), `parity_test` pass, `e2e_smoke` both instances + **new** `portfolio_test.py` (two fake bots share one ledger, hit gate, both blocked).
8. **Deploy** `main` → single cron restart (gold-only still default). Verify `btc/server_check.py` shows `portfolio` healthy.
9. **BTC data:** pull `BTCUSD_M5_pre_inspected.csv` + `M15` on `scalping` (where bridge lives). Run Phase-1c gate — **no LIVE enable** until it passes.
10. **Cleanup** next PR: remove root shims' `sys.modules` path, keep thin re-exports for one more release.

Paper book continuity: `logs/gold/paper_account.json` and `logs/btc/paper_account.json` stay at same `LOG_DIR` — the "100+ paper trades" clock in `HANDOFF.md` §5 does **not** reset if we don't move `LOG_DIR`. If we must move, copy the JSON.
